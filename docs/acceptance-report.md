# Acceptance report

Date: 2026-10-22. Commit under test: a9c3886 plus the uncommitted `test/acceptance/` suite.
Host: vps2 (Linux, tuios at /usr/local/bin/tuios, `fdfind` at /usr/bin/fdfind, vim present).
Run: `scripts/acceptance.sh` (it calls `scripts/remote.sh acceptG 840 -- go test -tags acceptance -count=1 -timeout 12m ./test/acceptance/...`).
Result: 8/8 tests PASS in about 2 s of test time.

Every test that needs a daemon starts its own server, named `cmt-<8hex>`. The spec's `clean-mtm-test-<id>` cannot be used because TUIOS caps server names at 14 characters. Each test also uses a temp SQLite DB and finite context deadlines. A deferred cleanup runs `kill-server` on that server only and removes that server's socket and state directories, even when the test fails. The default daemon is only read, with `tuios ls --json` and a scrubbed env.

## Unverified platform or remote behaviour

- macOS: the picker with `fd` and the socket base `/tmp/tuios-<uid>` were not exercised by this suite.
- Remote hosts: there is no configured host, so remote isolation and the refusal path are unverified.
- Real agent harnesses and prompt delivery against a live agent were not run.
- The full interactive TUI (`app.Run` under a real terminal, including `mtm-only` placement) and the interactive JSON explorer were not driven.

## Findings

1. Preview alt-screen detection: `get-window` and `capture-pane` on `tuios dev+b0a3712da4dc` do not include `alt_screen`. `preview.CaptureSync` reads `alt_screen`/`alternate_screen` from `get-window` and `alt_screen` from `capture-pane`, so AltScreen is never set. The capture still works because "recent" includes the visible screen. No product change was made.
2. Lease observability: list-windows and get-window `width`/`height` are the requested size (80x24), and the actual PTY under the frame was 78x22. Anything that wants the live size must use stream frames. This is documented here only; no product change was made.
